**Common strict mode errors and fixes:**

**1. Strictnullchecks errors (Object is possibly 'undefined'):**
```typescript
// Before (error)
const user = await User.findById(id);
res.json({ data: user.username }); // Error: user is possibly undefined

// After (fixed)
const user = await User.findById(id);
if (!user) {
  res.status(404).json({ success: false, error: 'User not found' });
  return;
}
res.json({ data: user.username });
```

**2. Implicit any in catch blocks:**
```typescript
// Before (error)
catch (error) { // Error: 'error' implicitly has type 'any'
  console.error(error.message);
}

// After (fixed)
catch (error: unknown) {
  const message = error instanceof Error ? error.message : 'Unknown error';
  console.error(message);
}
```

**3. Potential null access with process.env:**
```typescript
// Before (error)
jwt.sign(payload, process.env.JWT_SECRET); // Error: possibly undefined

// After (fixed)
const secret = process.env.JWT_SECRET;
if (!secret) {
  throw new Error('JWT_SECRET is not defined');
}
jwt.sign(payload, secret);
```

**4. Unused parameters:**
```typescript
// Before (warning)
const middleware = (req, res, next) => { // 'res' is unused
  next();
};

// After (fixed)
const middleware = (req: Request, _res: Response, next: NextFunction) => {
  next();
};
// Use _ prefix for intentionally unused parameters
```

**5. Array methods returning undefined:**
```typescript
// Before (error)
const user = users.find(u => u.id === id);
console.log(user.name); // Error: user is possibly undefined

// After (fixed)
const user = users.find(u => u.id === id);
if (user) {
  console.log(user.name);
}
```

**Fix strategy:**
1. Run `npx tsc --noEmit` to see all errors
2. Fix errors category by category:
   - First: Add null checks for undefined returns
   - Second: Type catch blocks as `unknown`
   - Third: Add environment variable validation
   - Fourth: Prefix unused params with underscore
3. Re-run compilation after each batch of fixes
4. Continue until no errors remain

The goal is zero TypeScript errors with strict mode enabled.
  </action>

    - No "implicitly has type 'any'" errors

**Common React strict mode errors and fixes:**

**1. Optional props without default values:**
```typescript
// Before (error)
interface Props {
  onSave?: (id: number) => void;
}
const Component: React.FC<Props> = ({ onSave }) => {
  onSave(123); // Error: onSave is possibly undefined
};

// After (fixed)
const Component: React.FC<Props> = ({ onSave }) => {
  if (onSave) {
    onSave(123);
  }
  // Or use optional chaining: onSave?.(123);
};
```

**2. useState with null initial values:**
```typescript
// Before (error)
const [user, setUser] = useState(null); // Type inferred as null
setUser({ id: 1, name: 'John' }); // Error: Type mismatch

// After (fixed)
const [user, setUser] = useState<User | null>(null);
setUser({ id: 1, name: 'John' }); // OK
```

**3. Array filter operations:**
```typescript
// Before (error)
const ids = items.map(item => item?.id); // Type: (number | undefined)[]
const validIds = ids.filter(id => id); // Type still includes undefined

// After (fixed)
const ids = items.map(item => item?.id).filter((id): id is number => id !== undefined);
// Or simpler: items.map(item => item.id) if items always have id
```

**4. Event target value access:**
```typescript
// Before (error)
const handleChange = (e: ChangeEvent) => {
  setValue(e.target.value); // Error: target might not have value property
};

// After (fixed)
const handleChange = (e: ChangeEvent<HTMLInputElement>) => {
  setValue(e.target.value); // OK: HTMLInputElement has value property
};
```

**5. Redux state selectors with nested properties:**
```typescript
// Before (error)
const userName = useAppSelector(state => state.auth.user.name); // Error: user is possibly null

// After (fixed)
const userName = useAppSelector(state => state.auth.user?.name);
// Or with default: state.auth.user?.name ?? 'Guest'
```

**Fix strategy:**
1. Run `npx tsc --noEmit` to see all errors
2. Fix errors by category:
   - First: Add null checks for optional props and state
   - Second: Type all useState hooks explicitly
   - Third: Add proper HTMLElement types to event handlers
   - Fourth: Use optional chaining for nested object access
3. Re-run compilation after fixes
4. Continue until no errors remain

The goal is zero TypeScript errors in all React components.

    - No "implicitly has type 'any'" errors
